# PLAN — 인력 에이전시 통합 관리 시스템 기능 계획서

> 목적: 카카오톡 오픈채팅방 + 문자 기반의 수동 인력 운영을 시스템으로 옮기기 위한 계획서다.
> 이 문서는 **무엇을 왜 만드는가**를 정한다. 화면 · 라우트 설계는 `docs/ADMIN_PLAN.md`,
> 코드 규칙은 `docs/DEVELOPMENT_GUIDE.md`를 본다.

---

## 1. 지금의 운영 방식 (As-Is)

```
오픈카톡방(약 1,500명)에 공고 게시
        ↓
문자로 지원 접수
        ↓
대표가 판단해 확정 → 문자로 통보
        ↓
행사 진행
        ↓
근로계약서를 문자로 발송 → 문자로 회수
   └ 잘못 쓰면 다시 요청 → 다시 회수
        ↓
첫 근무자면 신분증 · 통장사본을 문자로 수령
        ↓
정산
```

이 흐름 전체가 **대표 한 사람의 휴대폰 안에서** 돌아간다.

---

## 2. 해결해야 할 문제

| # | 문제 | 원인 | 이 시스템의 대응 |
|---|---|---|---|
| 1 | 모든 과정이 수동이다 | 데이터가 문자 · 카톡에만 있다 | 행사 · 인력 · 배치 · 계약 · 정산을 하나의 DB로 옮긴다 |
| 2 | 한 사람이 전부 쥐고 있다 | 권한을 나눌 도구가 없다 | 담당자 계정 · 권한 분리 · 운영 로그 (`/ops/managers`, `/ops/logs`) |
| 3 | 근로계약서 금액이 전부 같다 | 개별 작성할 인력이 없다 | 템플릿 + 변수 치환으로 **건별 자동 생성** (`/contracts`) |
| 4 | 블랙리스트가 체계가 없다 | 기준도 기록도 대표 머릿속에 있다 | 근태 기록 → 평판 점수 → 사유 필수 블랙리스트 (`/staff/blacklist`) |
| 5 | 부르던 사람을 또 부르는데 그 목록이 대표 머릿속에만 있다 | 기록할 곳이 없다 | 즐겨찾기(별 하나로 등록) + 좋아요 · 별로예요 기반 평판 점수 |
| 6 | 근무 전 공지 · 계약서가 자주 누락된다 | 매번 손으로 쓴다 | 행사 정보로 공고문 · 안내 문구 자동 생성, 미완료 건을 대시보드 최상단에 노출 |

> 3번은 계약서 자동 생성으로 푼다. 금액은 **배치 한 건(사람 × 날짜)마다** 다를 수 있고,
> 기준 설정의 시급은 행사를 만들 때 깔리는 초기값일 뿐이다.
> 사람마다 · 날마다 다르게 주기로 하는 일이 현장에서는 오히려 흔하므로,
> 금액은 행사 안에서 언제든 고칠 수 있어야 하고 계약서 · 정산이 그것을 따라와야 한다.

## 3. 도메인 모델

```
거래처(Client) 1 ──── N 행사(Event)
                          │
                          ├── N 직무 슬롯(EventRoleSlot)   발주 인원 · 기본 시급
                          │
                          └── N 배치(Assignment) ──── 1 인력(Staff)
                                    │                      │
                                    │                      ├── 서류(신분증 · 통장사본)
                                    │                      ├── 메모(StaffMemo)
                                    │                      └── 참여 이력
                                    │
                                    ├── 근태(AttendanceStatus)
                                    ├── 평가(좋아요 · 별로예요 + 항목)
                                    ├── 근로계약서(Contract)
                                    └── 정산(PayrollItem)

공고(JobPosting) ── N 지원(Application) ──▶ 확정 시 Assignment 생성
```

핵심 원칙

- **배치(Assignment)가 모든 것의 중심이다.** 계약서 · 정산 · 근태 · 평가가 전부 배치에 붙는다.
- **발주와 확정을 분리해 센다.** 그래야 캘린더에서 `SV 0/1 · ST 5/10`을 그릴 수 있다.
- **계산식은 한 곳에만 둔다.** 지급액은 `src/type/payroll.ts`의 `calculatePayroll`,
  평판 점수는 `src/type/staff.ts`의 `calculateReputationScore`.
  화면 · 목업 · 내보내기가 같은 함수를 쓴다.

## 4. 기능 명세

### 4.1 행사 일정

| 기능 | 내용 |
|---|---|
| 월간 · 주간 캘린더 | 한 칸에 행사 카드. 카드마다 직무별 `확정/발주` 칩 |
| 충원 상태 색상 | 0명 빨강 · 부족 주황 · 완료 초록 · 초과 파랑 |
| 빈 날짜 클릭 등록 | 캘린더 칸의 `+`를 누르면 그 날짜로 행사 등록 폼이 열린다 |
| 행사 상세 페이지 | 개요 · 일별 근무자 · 출퇴근 명부 · 근로계약서 · 정산 · 안내 6탭. 행사 하나를 여기서 끝낸다 |
| 상태 흐름 | 작성중 → 모집중 → 배치완료 → 진행중 → 정산대기 → 완료 (취소는 별도) |
| 날짜를 넘기는 근무 | 종료 시점을 당일 · D+1 · D+2에서 고른다. 방송 현장은 24시간을 넘겨 일한다 |
| 다일 행사 | 시작~종료일 사이 모든 날짜 칸에 표시 |
| 마진 표시 | 거래처 청구 시급 × 인원 − 인건비를 상세에서 즉시 계산 |

### 4.2 인력 배치

| 기능 | 내용 |
|---|---|
| 후보 추천 | 즐겨찾기 → 해당 거래처 경험 → 평판 → 누적 근무 순으로 점수화해 정렬 |
| **중복 배치 차단** | 같은 날 다른 행사에 확정된 인력은 목록에서 제외하고 선택도 막는다 |
| 배치 상태 | 제안 · 확정 · 대기 · 취소 |
| 적용 금액 | 직무 기본 금액에서 출발하되 **배치 건마다 언제든 수정** (사람별 · 날짜별) |
| 근태 기록 | 정상 · 지각(분) · 조퇴 · 결근 · 노쇼 → 인력 누적 지표에 반영 |
| 행사 후 평가 | 좋아요 · 별로예요 + 평가 항목 + 메모 → 평판 점수에 반영 |
| 안내 문구 자동 생성 | 집합 장소 · 복장 · 준비물이 빠지지 않는 문구를 만들어 복사 |
| 연락처 일괄 복사 | 확정 인원의 번호만 / 명단 형태 두 가지 |

### 4.3 모집

| 기능 | 내용 |
|---|---|
| 공고 생성 | 인원이 덜 찬 행사만 선택지에 노출 |
| **공고문 자동 작성** | 근무일 · 시간 · 시급 · 집합 · 복장 · 준비물이 포함된 초안 생성 |
| 복사 버튼 | 오픈카톡방에 그대로 붙여넣는다 |
| 지원 등록 | 문자로 받은 지원을 옮겨 적는다. 번호가 같으면 기존 인력에 자동 연결 |
| 신규 지원자 구분 | 인력풀에 없는 지원자는 배지로 표시 (서류부터 받아야 하는 대상) |
| 확정 처리 | 확정하면 **행사 배치까지 한 번에** 생성. 중복 일정은 서버가 거절 |

### 4.4 인사관리

| 기능 | 내용 |
|---|---|
| 인적사항 | 이름 · 연락처 · 생년월일 · 성별 · 프로필 · 지역 · 신체 정보 · 비상 연락처 |
| 보안 문서 | 신분증 · 통장사본 이미지. **기본은 가려 두고 눌러야 보인다** |
| 계좌 정보 | 대표 권한에서만 열람 (`canViewPayrollDetail`) |
| 참여 이력 | 행사 · 직무 · 근태 · 평가 · 지급액 |
| 근로계약서 이력 | 그 인력이 작성한 계약서 목록 |
| 메모 | 타임스탬프 메모. `주의 메모`는 상세 상단에 경고로 뜬다 |
| 평판 점수 | 좋아요 · 별로예요 건수로 계산 (표본 수를 반영해 기본 3.6에서 출발) |
| 서류 관리 화면 | 미제출 인력만 따로 모아 본다 |
| 블랙리스트 | **사유 없이 지정할 수 없다.** 노쇼 기준 초과자는 '지정 후보'로 자동 노출 |
| 즐겨찾기 | 목록에서 별 하나로 등록 · 해제. 배치 후보 추천에서 최상단으로 올라간다 |

### 4.5 근로계약

| 기능 | 내용 |
|---|---|
| 템플릿 | 직무별 양식. `{{이름}}` `{{시급}}` 등 변수 사용 |
| 검증 | 본문에 임금 변수(`{{시급}}` 또는 `{{총지급액}}`)와 `{{이름}}`이 없으면 저장 불가 |
| 일괄 생성 | 행사 단위로 확정 인원 전체의 계약서를 한 번에. 이미 있는 건은 건너뛴다 |
| 상태 | 작성됨 → 발송됨 → 서명완료 / 반려 / 기한만료 / 재작성됨 |
| 배치 연동 | 서명 완료로 바꾸면 배치 현황의 계약서 상태도 함께 바뀐다 |
| 근무일별 금액 | 계약서가 근무일마다의 지급 조건을 들고 있다. 날마다 다르면 임금 조항에 날짜별로 적는다 |
| 중도 종료 · 재작성 | 실제 근무일만 남긴 다음 차수를 만든다. 배치 취소 · 정산 재계산까지 한 번에 |
| 미리보기 | 변수가 채워진 최종 본문. 복사해서 문자로 보낼 수 있다 |

> **중도 종료를 왜 계약서에 붙였나.**
> 3일로 계약한 사람이 하루 만에 그만두는 일은 드물지 않다. 이걸 손으로 처리하면
> ① 남은 날 배치를 지우고 ② 계약서를 새로 써서 다시 받고 ③ 정산 금액을 깎는
> 세 가지 일이 세 화면에 흩어진다. 하나만 빠뜨려도 **계약서에는 3일치, 통장에는 1일치**가 되어
> 근거 없는 지급이 된다. 그래서 "실제로 나온 날이 어디까지인가" 하나만 고르면
> 나머지가 따라오게 묶었다.
>
> 옛 계약서는 지우지 않고 `재작성됨`으로 남긴다. **왜 금액이 달라졌는지를 설명할 근거**이기 때문이다.
> 새 차수에는 제외된 근무일과 사유가 문서 본문에 그대로 들어가고, 서명은 처음부터 다시 받는다.
> 이전 차수의 서명은 바뀐 근무일 · 금액에 대한 동의가 아니다.

### 4.6 정산

| 기능 | 내용 |
|---|---|
| 자동 계산 | 기본급 + 연장(8h 초과 0.5배) + 야간(22시 이후 0.5배) + 수당 − 차감 |
| 원천징수 | 사업소득 3.3% (기준 설정에서 변경 가능) |
| 지각 차감 | 분 단위로 시급을 깎는다 |
| 상태 | 정산대기 → 지급승인 → 지급완료 / 보류 |
| 보류 사유 | 계좌 미등록 건은 자동으로 보류 처리 |
| **은행 이체 파일** | `은행 / 계좌번호 / 예금주 / 금액 / 적요` 순서 CSV. 계좌 미등록 건은 자동 제외 |
| 상세 CSV | 수당 · 차감 · 원천징수까지 포함한 회계 확인용 |

### 4.7 거래처

| 기능 | 내용 |
|---|---|
| 직무별 청구 단가 | 행사별 마진 계산의 기준 |
| 누적 매출 · 인건비 · 마진율 | 마진율 20% 미만은 붉게 표시 |
| 거래 상태 | 종료한 거래처는 목록에서 구분 |

### 4.8 공지 · 발송

| 기능 | 내용 |
|---|---|
| 대상 선정 | 행사 확정 인원 중 선택. 계약 미완료자는 배지로 표시 |
| 템플릿 | 상황별(확정 안내 · 출근 리마인드 · 계약서 요청 · 서류 요청 · 정산 안내) |
| 변수 치환 | 계약서와 같은 `{{변수}}` 문법. 첫 수신자 기준 미리보기 제공 |
| 바이트 계산 | 한글 2바이트. SMS 90바이트 초과 시 LMS 전환 안내 |
| 발송 이력 | 언제 · 누가 · 몇 명에게 · 무엇을 보냈는지 기록 |

> **외부 연동 전이다.** 지금은 대상 · 문구 · 이력만 시스템에 남고 실제 문자는 나가지 않는다.
> 알리고 · 쿨에스엠에스를 붙이면 `POST /admin/messages/send` 핸들러만 교체된다.

| 기능 | 내용 |

## 5. 이번 범위에서 제외한 것

| 항목 | 이유 | 대안 |
|---|---|---|
| 로그인 · 권한 게이트 | 서버 인증이 없다 | `useAdminStore`의 고정 값. 붙일 때 두 곳만 수정 |
| 실제 문자 발송 | 외부 API 계약 필요 | 대상 · 문구 · 이력까지만 처리하고 문구를 복사해 발송 |
| 전자서명 | 서명 인증 수단 필요 | 상태 값(발송 · 서명완료)으로 진행만 추적 |
| PDF 생성 | 서버 렌더링 필요 | 변수 치환된 본문을 복사 |
| XLSX 내보내기 | 라이브러리 추가 필요 | BOM 포함 CSV (엑셀에서 한글이 깨지지 않는다) |
| 근로자용 앱 | 다음 단계 | 지금은 사내 웹. 앱이 붙으면 지원 접수만 자동화되고 이후 흐름은 그대로 |

## 6. 다음 단계 (앱 연동 이후)

1. 근로자가 앱에서 공고를 보고 직접 지원 → `Application`이 자동 생성된다.
2. 지원 시점에 인력 정보 · 서류가 함께 들어오므로 **신규 지원자 등록 단계가 사라진다.**
3. 현장에서 QR · GPS로 체크인하면 `Assignment.attendance`가 자동으로 채워진다.
4. 근태가 자동으로 쌓이면 **평판 · 블랙리스트가 사람 손 없이 굴러간다.**

이 시스템은 그 흐름의 **관리자 쪽 절반**을 먼저 만들어 둔 것이다.
데이터 모델과 API 형태를 앱 연동을 전제로 잡아 두었기 때문에,
서버가 붙을 때 화면 코드는 거의 그대로 쓸 수 있다.
